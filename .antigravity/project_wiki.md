# AppBana Project Wiki 🧠

> **For Future Agents**: Read this document to instantly understand the system architecture, component model, and critical "tribal knowledge" regarding past fixes.

## 1. System Architecture

AppBana is a low-code application builder with a distinct **Builder** (Design Time) and **Runtime** (Production) split.

### Frontend (`app-bana-ui`)
Built with **LitElement** (Web Components) and TypeScript.

- **Builder (`src/builder`)**:
    - `LivePreview.ts`: The drag-and-drop canvas. It handles selection, hovering, and emits events for the store.
    - `LivePreview.css`: Contains builder-specific styles (e.g., dotted lines, empty hints). **Crucial**: This file defines CSS variables that conceal "Builder Hints" from the Runtime.
    - `PropertiesPanel.ts`: The side panel for editing component props.
    - `ComponentLibrary.ts`: Drag source for new components. *Note: Defines default props/styles for new nodes.*
    - `TreeStore.ts`: MobX-like state store managing the component tree.

- **Runtime (`src/runtime`)**:
    - `AppRuntimeShell.ts`: The main shell for the running app. Handles routing and page switching.
    - `Renderer.ts`: The engine that takes a JSON `ComponentNode` tree and renders DOM/Lit elements.
    - **Isolation**: The Runtime does NOT load `LivePreview.css`. It relies on the components' shadow DOM or their intrinsic styles.

### Backend (`app-bana-service`)
Java, Vert.x-based service.
- Handles app persistence, AI generation, and data storage.
- Storage: File-based JSON (currently).

## 2. Component System

Components are Custom Elements (e.g., `<studio-input>`, `<app-grid>`).

- **Registry**: `src/core/registry.ts` maps type strings (e.g., "input") to Classes.
- **Common Base**: `BaseElement` or `FormElement`.
- **Styling**: Components use Shadow DOM. Global styles (like Bootstrap/Tailwind) might not penetrate unless explicitly adopted. We currently use vanilla CSS in `index.css` and component-specific styles.

### Key Components
- **`app-grid` (`GridElement.ts`)**: CSS Grid based. Supports custom rows/cols.
    - *Key Feature*: Uses CSS variables for borders/labels to support "Ghost Mode" in Builder vs Clean Mode in Runtime.
- **`studio-container` (`ContainerElement.ts`)**: Flexbox container.
    - *Note*: Default styles are plain (no border/padding).

## 3. Critical Knowledge / Lessons Learned 💡

### The "Grid Layout Gap" Saga (Dec 2025)
**Problem**: Users reported persistent 16px gaps and dotted lines in the Runtime, even when Gap was set to 0.
**Root Causes**:
1.  **Hidden Defaults**: `ContainerElement` had a hardcoded `border: 1px dashed` and `min-height: 50px`.
2.  **Legacy Data**: Old grids had `padding: 0.5rem` hardcoded in their JSON `props.style` (generated by an older `ComponentLibrary.ts`).
3.  **Global Css**: `LivePreview.css` had a generic `margin: 4px 0` on all inputs.

**The Fixes (Do Not Revert)**:
1.  **Sanitization**: `LivePreview.ts` and `Renderer.ts` both contain "Hotfix Logic" to intercept `grid-cell` nodes and strip `padding/gap` attributes from their inline styles.
2.  **CSS Variables**: `GridElement` uses:
    ```css
    border: 2px dashed var(--grid-outline-color, transparent);
    display: var(--grid-key-display, none);
    ```
    These variables are **ONLY** defined in `LivePreview.css`. In Runtime, they fall back to `transparent`/`none`, ensuring a clean look.
3.  **Zero-Tolerance Layout**: Input defaults are `margin: 0`.

### Rendering Discrepancies
- **Problem**: "It works in Canvas but not Preview."
- **Reason**: Canvas uses `LivePreview.ts` (Lit Template). Preview uses `Renderer.ts` (Recursive Function).
- **Solution**: Always apply render-logic fixes (like data injection or style sanitization) to **BOTH** files.

### 3a. Critical Development Rules ⚠️

> **THE GOLDEN RULE**: If you change the code, you MUST update the AI Brain.

The AI Agent generates code based on the JSON definitions in `builder-database/`.
If you modify a component (e.g., add a prop to `GridElement`), but fail to update `builder-database/02-components.json`, the AI will **not know** about your change and will generate broken/outdated code.

**Workflow**:
1.  Modify TS Component (`src/components/...`).
2.  Update relevant JSON in `builder-database/` (e.g., `02-components.json`).
3.  Commit both.
