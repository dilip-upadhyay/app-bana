# UI Development Plan — Custom UI Core ("Studio")

This document outlines the development plan for AppBana's custom UI framework, codenamed "Studio". This plan supersedes all previous plans, including the one based on Angular.

## 1. Vision & Core Principles

The goal is to create a powerful, lightweight, and maintainable no-code/low-code UI development platform that is perfectly tailored to the AppBana backend.

- **Component-Based:** The architecture is built on standard Web Components for maximum interoperability and longevity.
- **Metadata-Driven:** All UIs are rendered from a JSON metadata definition. This separates the "what" from the "how".
- **TypeScript First:** The entire frontend codebase will be in TypeScript for robustness, maintainability, and excellent tooling.
- **Minimal Dependencies:** We will avoid large, opinionated frameworks. Dependencies will be chosen carefully for specific tasks (e.g., `vite` for the build tool).
- **Extensible:** The framework will be designed from the ground up to support plugins for custom components, data connectors, and actions.

## 2. Core Components of "Studio"

The "Studio" framework consists of two main parts:

1.  **The Builder:** A visual, no-code canvas application. Users will drag and drop components, configure their properties, and arrange them to design application UIs. The output of the builder is a metadata JSON file that describes the UI.
2.  **The Runtime:** A lightweight but powerful rendering engine. It takes the metadata JSON generated by the builder and dynamically renders the final, interactive user application in the browser.

## 3. Technology Stack

- **Language:** TypeScript
- **Core Technology:** Native Web Components (Custom Elements, Shadow DOM)
- **Development & Build Tool:** Vite
- **Initial Component Helper:** `lit` will be used as a temporary, lightweight helper to accelerate initial development. It will be phased out over time.

## 4. Phased Development Plan

The development will proceed in phases to manage risk and ensure continuous progress.

-   **Phase 0 (Current):**
    -   Utilize `vite` as the primary build tool and development server.
    -   Use `lit` as a temporary helper to be productive in building the first set of components.

-   **Phase 1 (Incubate):**
    -   Introduce a custom `BaseElement.ts` class. This will be the foundation for all future UI components in our ecosystem.
    -   This base class will manage the component lifecycle, a shadow root for encapsulation, a simple reactive state model, and a `render()` method.

-   **Phase 2 (Adopt):**
    -   Begin building all new UI components for both the **Builder** (e.g., property inspectors, canvas elements) and the **Runtime** (e.g., form inputs, data tables) using the internal `BaseElement` core.

-   **Phase 3 (Migrate):**
    -   Incrementally replace the initial components that were built with `lit` with new versions built on our `BaseElement`.
    -   The end goal of this phase is to completely remove the `lit` dependency, leaving us with a fully custom, self-contained UI framework.

This strategic, phased approach allows us to build a powerful, custom platform while maintaining development velocity and mitigating the risks associated with building a framework from scratch.
